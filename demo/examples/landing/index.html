What ships by default

A small starter surface with explicit responsibilities.

The landing page should orient a new user quickly: what the runtime owns, what analytics owns, and where to go next when they want the fuller example.

01 · Runtime core

Bootstrap the shell, then keep the runtime quiet.

EventBus, ServiceManager, and Contracts establish the runtime boundaries. LogAccumulator stays on the local side of the line and never becomes the outbound telemetry system.

  • Lifecycle-safe module registration
  • Local diagnostics and error-boundary capture
  • Contracts-first validation for runtime payloads
02 · Observability

Analytics is a separate module, not a UI helper.

Page views, consent, SEO metadata, and telemetry batching stay inside AnalyticsService so the runtime can remain lean.

  • Consent-scoped outbound tracking
  • SEO-enriched pageview snapshots
  • SSMA query boundary alignment
03 · Starter UI

Three primitives, one focused demo.

Button, Badge, and Toast remain in the starter set. The todo example shows how a real flow layers state, theme cycling, and persistence on top.

  • Theme tokens shared across pages
  • Todo app as the richer reference flow
  • Docs and skills for implementation details

How it fits together

The page should teach the architecture at a glance.

This is the place for a compact explainer, not a generic feature list. The sequence below mirrors how the runtime behaves in practice.
